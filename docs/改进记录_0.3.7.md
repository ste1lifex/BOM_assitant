# 0.3.7 改进记录（第三轮复测修复）

> 依据：`Recording_card/docs/工具改进建议_第三轮_0.3.6复测.md`（R3）。
> 验收：`node poc/validate.mjs`（182 项离线全过）+ 3 个外部测试 BOM 的本地审计（不随仓库提供）。

## B1（P0）基础库替代净省回归 — 已修

根因：0.3.6 的 stock-aware 改造把 `best` 指向了 `entry.score`，而 `net/componentDelta` 在 `entry` 上，导致 `NaN → null`、净省被当 0。

- 修复后：BOM v0.6、100 片、`require_stock=smt`：`C114765 → C25092`，**net $2.55**，`component_delta $0.45`，扩展库 **12→11**。
- 净省改为纯 USD 计算；CNY/库存只参与过滤与展示，不再影响 net。

## B2（P1）手焊模式增加 retail 缺货替代 — 已修

- hand 模式对 `stock_retail=0` 的料号搜索同品类替代，输出 `optimize.retail_alternatives` + 中文建议行。
- 验收（BOM v0.6 hand）：`C25744`（零售 0 / SMT 2062 万）→ 找到立创零售有货替代（¥0.0021、库存 412 万）。

## B3（P2）USD 模式隐藏 CNY 估算列 — 已修

- `include_cny=false` 时移除 audit 行的 `unit_cny_estimate/subtotal_cny_estimate` 与 summary 估算字段；find 同理移除 `price_cny/cny_estimate/cny_price`。
- 纯 USD 输出行内不再出现 `CNY≈...(est.)`；需要估算请 `include_cny=true`（CNY 不可达时仍给 estimated）。

## B4（P2）`cny_jlc_cn` 残留旧 note — 已修

- `region=cn` 的「仍按 USD 上料费估算」note 只在非 `cny_jlc_cn` 时出现；`cny_jlc_cn` 输出只保留人民币费率说明。

## B5（P2）retail 有货优先 — 已修

- hand + CNY 模式下，同等相关性时优先 `stock_retail>0` 的候选，再按原排序。

## B6（P2）结构化字段在文本输出可见 — 已修

- audit 行文本增加 `{src=... cny_src=... asof=... cover=...}`，一次调用即可看到 `price_source`/`stock_asof`/`coverage`。

## 性能修复（本轮额外）

- CNY 失败**负缓存 30min**（`cnNegativeCacheTtlMs`），坏料号不再每次重跑都等；
- product-id 解析改为 **EasyEDA/lceda 并行 + 8s 上限**（原先串行 2×30s）；
- C+10 位长料号渲染上限 12s；page-parse-failed 不再做第二次 30s 重试。
- 实测：问题料号首次 65s → 17s，重查 0.001s；第三个 BOM 的 CNY 审计从 67s（每次）→ 0.02s（缓存后）。
